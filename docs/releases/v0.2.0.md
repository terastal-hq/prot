## prot 0.2.0

0.2.0 adds SSH tunnels, which is the biggest thing since 0.1.0, makes the MCP server and the supervisor more trustworthy,
and gives prot a website. It is mostly additive, but there are a few behaviour changes you should read before upgrading.

### SSH tunnels

Reach a port on another machine at a stable name, the same way you reach a local server:

```bash
prot tunnel add proxmox --host root@192.168.0.109 --remote-port 8006 --auto-connect
# http://proxmox.localhost:8080 now reaches port 8006 on that machine
```

- **Real OpenSSH.** prot runs your system's `ssh`, reconnects when the link drops, and only reports a tunnel as
  connected once the forwarded port actually answers. Tunnels are restored when `protd` starts and stopped when it exits.
- **Machines from `~/.ssh/config`.** `--host` accepts a name from your SSH config (`prot ssh ls` lists them), and the desktop
  app offers them in a dropdown with their user, port and key prefilled. Change nothing and the tunnel keeps following
  your config.
- **Passwords and key passphrases** are kept in the OS keyring (Secret Service on Linux, Keychain on macOS), never in
  prot's database, logs or a command line. Add one with `--password` or `--password-stdin`, change or clear it with
  `prot tunnel password`. prot refuses to store a password at all if there is no keyring.
- **Edit in place.** `prot tunnel edit`, the settings button on a tunnel card and `PATCH /v1/tunnels/{id}` change a tunnel
  without recreating it. A connected tunnel reconnects with the new settings; a stopped one stays stopped. Renaming moves
  its `.localhost` address.
- **Desktop app.** A Tunnels tab to create, edit, start, stop and delete tunnels, with the reason shown when one cannot
  connect (host key not trusted, wrong password and so on). prot never accepts an unknown host key for you.
- **Agents.** The MCP server gains `list_tunnels`, `start_tunnel` and `stop_tunnel`. Creating or editing a tunnel and
  touching a password are deliberately not available to agents: that would let one open an SSH connection to an
  arbitrary host.

See [docs/tunnels.md](https://github.com/terastal-hq/prot/blob/main/docs/tunnels.md) for setup (keys, host keys) and
troubleshooting.

### Desktop app

- Removing a server or a tunnel now asks "Remove this ...?" inline, with Cancel and Delete. It never times out, and
  Escape cancels.
- The New Tunnel sheet has SSH user and port fields next to the host.

### MCP server

- **`prot mcp` is now a thin bridge to the running `protd`** instead of a second supervisor of its own. An agent sees the
  same services, logs and process state as the CLI and the desktop app, and processes it starts keep running when the agent
  disconnects. `protd` must be running (`systemctl --user start protd`); otherwise the bridge says so clearly.
- Every tool that targets a service takes `id_or_alias`, `set_alias` renames a real service, stopping an already
  stopped service succeeds, and notifications no longer get a reply.

### Reliability and security

- **Supervisor rewritten** around a per-run completion channel, fixing races around restarts and stops. Crash restarts
  back off exponentially and a run that lasts 10 seconds resets the backoff.
- **`prot update` verifies downloads** against `checksums.txt`, caps download sizes, stages both binaries before replacing
  either, and refuses to run at all on installs managed by a package manager (it points you at pacman, apt or dnf).
- **Management API**: removed an unused empty-token bypass; tests now cover that it fails closed.
- Followed logs (`prot logs -f`) are delivered exactly once; the gateway no longer reserves `/v1/` and `/mcp` paths that
  belong to your apps; start, stop and restart of an unknown service return 404.
- The database now has versioned migrations and trims its event log. Upgrading migrates it automatically (to schema
  version 3); there is no way back to 0.1.0 with the same data directory.

### Website

prot has a landing page, at the project's GitHub Pages address, built from real captures of the app and real CLI output.

### Changes to be aware of

- **Windows is not a target.** It was never released; the leftovers are gone, and the support matrix lists Linux and macOS.
- **`set_alias` (MCP) no longer accepts `target_url`.** It renames a service's alias.
- **`protd` honours `PROT_DATA_DIR`**, like the CLI always did.
- If `protd` is killed with SIGKILL it can leave `ssh -N -L` processes behind; a normal stop cleans up. This is
  documented in the tunnels guide.

### Install or upgrade

```bash
curl -fsSL https://raw.githubusercontent.com/terastal-hq/prot/main/scripts/install.sh | bash   # or: prot update
yay -S prot prot-desktop                                                                         # Arch
systemctl --user restart protd
```
