## prot 0.2.1

A small release: shell tab completion, a multiline command field in the desktop app, and a fix for the Arch packages. There
are no daemon or API changes, and nothing to migrate.

### Tab completion

`prot` now completes in bash, zsh and fish. `prot completion <shell>` prints the script, which asks `prot` itself for
suggestions, so the three shells agree.

- Commands, subcommands and options complete.
- The daemon supplies service and tunnel aliases, discovered process ids, and the machines in `~/.ssh/config`. Each
  lookup waits at most 1.5 seconds and stays silent when the daemon is down.
- The `.deb`, `.rpm` and AUR `prot` packages install the scripts where the shells read them on their own, and the release
  archive carries them. The curl installer writes them to your user directories for the shells it finds. Two shells need
  a step of their own (bash without the `bash-completion` package, zsh without the directory on `fpath`), described in the
  [installation guide](https://github.com/terastal-hq/prot/blob/main/docs/installation.md).

### Desktop app

- The **Command** field of the New Server and Edit Server sheets is a multiline text area. Lines wrap at the edge, the
  box is as tall as its text (never fewer than three lines) and has no drag handle. Enter adds a line and Ctrl or Cmd +
  Enter creates or saves. The daemon already runs commands through `sh -c`, so each line runs in turn. A server card shows
  the first line with a mark for the lines that follow.

### Arch Linux

- **`yay -S prot` no longer compiles the desktop app.** The three packages used to share one PKGBUILD, and makepkg runs the
  build once for all of them, so installing the CLI built the Tauri app and pulled in Rust, Node and WebKit. `protd` and
  `prot` are now their own AUR package, built from Go alone, and `prot-desktop` is a separate package that builds only
  when you install it. The package names and what they contain are unchanged.
- The previous AUR package, `0.2.0-1`, installs the desktop app together with everything else and was built before the
  completions existed. `0.2.1-1` replaces it.

### Other

- A GitHub release is now marked as the latest release and not a pre-release when the workflow finishes. Until now
  `prot update` and the install script could not find the newest version unless that was changed by hand.
- Documentation: a [roadmap](https://github.com/terastal-hq/prot/blob/main/docs/roadmap.md) for local HTTPS and public
  exposure. Both are proposals and neither is implemented.
- Website: social preview image and page metadata, install buttons for each platform, and a short install URL
  (`curl -fsSL https://prot.adityagupta.dev/install | bash`, which is the same script as before).
